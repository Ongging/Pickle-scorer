# External display plugin — setup

This gives the Android app real detection of HDMI/wired monitors and
most wireless "extend" displays, via `DisplayManager` — something a web
page can never see. It's written but **not compiled or tested** (this
environment can't reach the Android SDK/Gradle tooling); it needs
Android Studio on a real machine, same as the rest of the Capacitor
side of this project.

## What it can and can't see

- **Can see:** a wired/HDMI monitor, and wireless displays the OS
  treats as a genuine additional screen (most Miracast "extend"
  setups).
- **Can't see:** plain screen mirroring/casting where Android
  duplicates the same framebuffer instead of creating a second
  `Display` object — some OEM "Smart View" / cast implementations work
  this way. That's a real Android platform limitation, not something
  fixable from plugin code.

## Setup (run once per fresh `android/` folder)

The `android/` folder itself is git-ignored and regenerated by
`npm run cap:add:android` — so this plugin's source lives here, outside
it, and gets copied in after each regeneration.

1. Build and add the platform if you haven't already:
   ```
   npm run build
   npm run cap:add:android
   ```

2. Copy the plugin file into the generated project, next to
   `MainActivity.java`:
   ```
   cp android-plugin/ExternalDisplayPlugin.java \
      android/app/src/main/java/com/example/pickleballscorer/
   ```
   (If you've since changed `appId` in `capacitor.config.json` away
   from the `com.example.pickleballscorer` placeholder, use the
   matching package path under `android/app/src/main/java/` instead,
   and update the `package` line at the top of
   `ExternalDisplayPlugin.java` to match.)

3. Register the plugin in `MainActivity.java`
   (`android/app/src/main/java/com/example/pickleballscorer/MainActivity.java`).
   It currently reads:
   ```java
   package com.example.pickleballscorer;

   import com.getcapacitor.BridgeActivity;

   public class MainActivity extends BridgeActivity {}
   ```
   Change it to:
   ```java
   package com.example.pickleballscorer;

   import android.os.Bundle;
   import com.getcapacitor.BridgeActivity;

   public class MainActivity extends BridgeActivity {
       @Override
       public void onCreate(Bundle savedInstanceState) {
           registerPlugin(ExternalDisplayPlugin.class);
           super.onCreate(savedInstanceState);
       }
   }
   ```

4. Sync and open in Android Studio to build:
   ```
   npm run cap:sync
   npm run cap:open:android
   ```

Once it's registered natively, the JS side in
`src/lib/externalDisplay.js` picks it up automatically — no other code
changes needed. Until step 3 is done, that file's native branch is a
harmless no-op (nothing registered → the listener call is caught and
just never fires), so the app works fine without this, using only the
web-side detection on any platform.

## Re-doing this after regenerating `android/`

Steps 2 and 3 need repeating any time you delete and re-add the
`android/` folder (e.g. `npx cap add android` again from scratch).
